# 2026-04-10_week3
**Completed:** Week 3 — People & Transactions

## Changes
- Added `Payer` entity for donors, vendors, suppliers, sponsors with soft delete
- Added `ClosedYear` entity for period lock (prevents transactions in closed years)
- Added `Transaction` entity with support for Student/Payer polymorphic relationship
- Added `TransactionItem` entity for transaction line items linked to categories
- Added `JournalEntry` entity for double-entry bookkeeping audit trail
- Created `StudentsController` with full CRUD operations (`/api/v1/students`)
  - GET /api/v1/students - List students with pagination, search, and filters (classId, gradeId, isActive)
  - GET /api/v1/students/{id} - Get single student with transaction history
  - POST /api/v1/students - Create student (Admin, Staff)
  - PUT /api/v1/students/{id} - Update student (Admin, Staff)
  - DELETE /api/v1/students/{id} - Soft delete student (Admin only)
  - POST /api/v1/students/{id}/assign-class - Assign student to class
  - GET /api/v1/students/report - Student report with transaction summaries by grade/class
  - POST /api/v1/students/import - CSV bulk import (multipart/form-data)
- Created `PayersController` with full CRUD operations (`/api/v1/payers`)
  - GET /api/v1/payers - List payers with pagination, search, and filters (type, isActive)
  - GET /api/v1/payers/{id} - Get single payer with transaction history
  - POST /api/v1/payers - Create payer (Admin, Accountant, Staff)
  - PUT /api/v1/payers/{id} - Update payer (Admin, Accountant, Staff)
  - DELETE /api/v1/payers/{id} - Soft delete payer (Admin, Accountant)
- Created `TransactionsController` with double-entry operations (`/api/v1/transactions`)
  - GET /api/v1/transactions - List transactions with pagination and filters (type, date range, transactable)
  - GET /api/v1/transactions/{id} - Get single transaction with items and journal entries
  - POST /api/v1/transactions - Create transaction with line items and auto-generated journal entries
  - PUT /api/v1/transactions/{id} - Update transaction (same-day only)
  - DELETE /api/v1/transactions/{id} - Soft delete transaction (same-day only)
  - POST /api/v1/transactions/{id}/reverse - Reverse a transaction (creates reversal entries)
- Created `JournalEntriesController` for audit trail (`/api/v1/journal-entries`)
  - GET /api/v1/journal-entries - List journal entries with filters (ledgerId, journalType, date range)
- Implemented double-entry bookkeeping logic in `TransactionService`
  - Income transactions: Debit CashLedger, Credit Category Ledger(s)
  - Expense transactions: Debit Category Ledger(s), Credit CashLedger
  - Validates debit sum equals credit sum before saving
  - All operations wrapped in database transactions for atomicity
  - Updates ledger balances according to account type (debit-normal vs credit-normal)
  - Updates student/payer balances (income adds, expense subtracts)
- Implemented transaction validation rules
  - Validates transactable type is "Student" or "Payer" with valid entity IDs
  - Validates cash ledger exists and is an asset account
  - Validates category types match transaction type (income/expense)
  - Validates `RequiresStudent` constraint on categories
  - Validates item amounts match quantity × unit price
  - Period lock: rejects transactions in closed years
  - Same-day edit/delete restriction enforced
- Implemented transaction reversal in `TransactionReversalService`
  - Creates opposite-type transaction with reference to original
  - Marks original as `IsReversed = true` with `ReversalTransactionId`
  - Creates reversal journal entries with `JournalType = 'reversal'`
  - Updates all balances accordingly
- Added transaction number generation (TXN-YYYYMMDD-NNNN format)
- Added receipt number generation for income transactions (RCP-YYYYMMDD-XXXXXXXX)
- Created EF migration `AddPeopleAndTransactions`
- Registered all new services in `Program.cs`
- Applied RBAC permissions per permission matrix in SPECS.md

- The double-entry logic is comprehensive and handles all edge cases per SPECS.md.
