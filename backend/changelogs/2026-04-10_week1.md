# 2026-04-10_week1

**Completed:** Week 1 — Foundation & Auth

## Changes

### Project Bootstrap
- Created .NET 10 Web API solution (`SchoolAccounting.slnx`) and project (`SchoolAccounting.Api`)
- Configured Entity Framework Core 10 with SQL Server provider
- Set up Vertical Slice Architecture folder structure:
  - `Infrastructure/` - Persistence, Auth, Middleware
  - `Common/` - Shared utilities, role definitions, exceptions
  - `Features/` - Auth, UserManagement (and placeholders for future features)
- Added global exception handling middleware with typed exceptions → HTTP status mapping
- Configured CORS policy to allow `http://localhost:3000` and `http://127.0.0.1:3000`
- Created initial EF Core migration (`InitialCreate`) for Users and PersonalAccessTokens tables

### Authentication & Authorization
- Implemented `BearerTokenAuthHandler` - custom authentication handler that validates tokens against database
- Token storage uses SHA-256 hashing (raw token returned once to client, only hash stored)
- Tokens have 30-day expiry with `LastUsedAt` tracking
- Role-based authorization using `ClaimTypes.Role` from ASP.NET Core (no extra libraries)

### Auth Endpoints (`/api/v1`)
- `POST /register` - Register new user, defaults to `Viewer` role
- `POST /login` - Authenticate and receive bearer token
- `POST /logout` - Revoke current token (requires auth)
- `GET /user` - Get current authenticated user info (requires auth)

### User Management (`/api/v1/users`, Admin only)
- `GET /users` - List users with pagination and search
- `GET /users/{id}` - Get specific user
- `POST /users` - Create new user with any role
- `PUT /users/{id}` - Update user name/username/email
- `PUT /users/{id}/role` - Assign role (with last-admin guard)
- `PUT /users/{id}/password` - Change user password
- `DELETE /users/{id}` - Delete user (with last-admin guard)

### Security Features
- Password hashing using BCrypt
- Last-admin guard: prevents demoting or deleting the only remaining admin user
- Unique constraints on email and username

### Database Seeding
- `DbInitializer` runs on startup, applies migrations automatically
- Seeds default admin account if no admin exists:
  - Email: admin@school.com
  - Username: admin
  - Password: ChangeMe123! (configurable via `AdminSeedPassword`)

### Documentation
- Created `README.md` with setup instructions, API endpoint documentation, and development guide
